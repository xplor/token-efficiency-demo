Cheat sheet
The goal isn't fewer tokens. It's more correct, verified progress per minute, per token and per prompt. Plan to keep the agent on target; manage context to keep it cheap.

3Planning keeps the agent on target

Every agent plans. Plan mode makes it plan where you can see it, so a wrong assumption costs one line to fix instead of a correction spiral, rework or a new session. Skip it for one obvious line.

Ask the plan for
Goal         one line, in your words
Change       the files it will edit
Don't touch  folders and files out of scope
Approach     where the logic goes, and why
Tests        cases, including the edge case
Verify       the exact commands
Open Qs      anything it had to guess

Then treat it as the contract

  • Approve only what you've actually read
  • Build only what's in the plan
  • New evidence → stop and re-plan, don't patch around it
  • "Don't touch" is what stops drive-by refactors
  • Open questions are where bugs hide: answer them
1 · PlanPlan mode (Shift+Tab in both CLIs). It explores; the window fills.
2 · Save"Write the approved plan to plans/<task>.md."
3 · Clear/clear. Exploration noise gone; the plan file and repo remain.
4 · Build"Implement plans/<task>.md." A fresh, small window.

The plan file doubles as your handoff. A plan that just restates your prompt cost tokens and bought nothing.

Vibe habits that burn tokens

  • "Fix it" prompts with no file, rule or test
  • One chat for every goal of the day
  • Attaching a whole folder "just in case"
  • Running the full test suite every turn
  • Five "no, not that" corrections in a row
  • The strongest model for a rename

5Continue, compact or clear?

SituationDoKeeps
Same goal, smallContinueEverything
Same goal, long chat/compact · /summarizeA summary you steer
New goal/clearRepo + plan file
Wrong turn/rewindAll before it
Reset when… the goal changes · it forgets a constraint you gave · it retries a failed fix · old logs no longer matter · context passes ~50% mid-task.
Compact well: at a boundary, not mid-edit · say what to keep · restate the key constraint afterwards · don't wait for auto-compact to choose for you.

Clearing isn't losing work: code, tests, docs, git and your plan file are the memory; the transcript is scaffolding. No plan file? Write a ≤ 200-word handoff first.

6Progressive disclosure for agent docs

0Always loaded · CLAUDE.md / AGENTS.md: commands, non-negotiables, pointersevery turn · keep to ~1 screen
1Routing map · docs/architecture.md: which file owns whatwhen locating code
2Scoped rules · .claude/rules/*.md with paths: · nested CLAUDE.md · Cursor: .cursor/rules/*.mdc with globswhen matching files are touched
3Deep docs · decision records, runbooks, skills, specsonly when changing that rule

Write pointers, not paragraphs: "Read docs/architecture.md only when you need to locate code." After a bad session, put the lesson at the narrowest layer where it will still be found, not in CLAUDE.md. Disable MCP servers you aren't using: their tool definitions load every session.
